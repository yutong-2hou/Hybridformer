# 后续开发任务建议

以下是建议创建的三个 Issue，尚未自动创建。优先完成 [Issue #1](https://github.com/yutong-2hou/Hybridformer/issues/1) 的可复现安装与最小流程，再按下面顺序推进。优先级含义：P0 阻塞基本运行，P1 阻塞可信的研究结论，P2 改善协作维护。

## 1. [P1] 明确时间序列数据协议并排查填充与缩放引入的评估偏差

**依据：** `data/data_loader.py` 在切分前执行全表 `ffill().bfill()`；`HybridScaler` 会裁剪所有输入及目标。比例模式的验证长度由余数决定，未直接使用第二个比例值。当前没有数据字典和有效性检查。

**工作范围：** 明确时间列、采样间隔、字段单位和数据来源/使用授权；定义训练、验证、测试的边界、缺失值策略和越界值策略，并将当前行为与修订协议分开记录。为变更前后使用同一数据快照建立比较。

**验收标准：**

- [ ] 数据字典覆盖 20 个输入、6 个目标的单位和顺序，说明数据许可与采样假设。
- [ ] 用包含边界缺失值的合成数据验证：训练处理不读取未来验证/测试值。
- [ ] 测试验证/测试的历史上下文合法，标签不跨越各自划分边界。
- [ ] 明确验证/测试目标是否裁剪，保留原始标签并量化当前裁剪影响。
- [ ] 校验缺列、非数值、重复/乱序时间戳、划分越界和窗口不足；给出可读错误。
- [ ] 写明比例/行数两种划分规则，并用边界用例固定行为。

**依赖：** Issue #1。

## 2. [P1] 核查编码器输出与梯度覆盖，建立可追踪的模型基线

**依据：** `Encoder.forward()` 初始将嵌入加入 `enc_out`，只在合并时追加输出，最后一层计算结果未加入返回列表。2026-10-26 在原始代码上以 `e_layers=2`、`d_model=32`、`d_ff=64` 的 CPU 小模型执行反向诊断，最后一层的 26 个参数均无梯度；仍需结合设计意图确认预期连接方式。`factor` 等参数的实际作用也需核对。当前没有随机种子、逐目标评估或实验环境记录。

**工作范围：** 先增加诊断与设计说明，确认模型意图后单独修复；不要把模型修复与文档整理混为一次变更。随后建立可以公平比较的简单基线和实验记录。

**验收标准：**

- [ ] 对默认 `e_layers=2` 执行前向与反向诊断，列出没有梯度的参数及其原因。
- [ ] 确认最后一层编码器输出是否应被解码器使用；按确认后的结构增加输出/梯度测试。
- [ ] 对 CLI 模型参数区分实际生效、兼容保留和未实现，并更新说明。
- [ ] 固定并记录 Python/NumPy/PyTorch 随机种子、设备、依赖版本、代码提交及数据摘要；说明设备确定性限制。
- [ ] 在统一协议下比较持久性预测与模型，报告逐目标、逐预测步 MAE/RMSE，定义零值时的比例指标策略。
- [ ] 使用唯一实验目录，记录完整参数与缩放状态；至少重复 3 个种子并报告均值及离散程度。

**依赖：** Issue #1；正式结果依赖上述数据协议任务。

## 3. [P2] 清理仓库生成物并建立贡献与实验产物约定

**依据：** 仓库跟踪了 `.DS_Store`、`__pycache__`、`.pyc`，同时将历史权重、预测数组与源码放在一起；缺少许可证、贡献说明和任务模板。

**工作范围：** 增加忽略规则和协作规范；为数据、权重及实验结果选择保留、归档或外部存储策略，并保留历史结果的来源链接。任何产物迁移前先确认可恢复。

**验收标准：**

- [ ] `.gitignore` 覆盖系统文件、Python 缓存、虚拟环境和新实验输出；已跟踪的缓存从版本索引移除。
- [ ] 数据与模型产物分别记录来源、校验和、对应配置及获取方式；历史研究产物不会被误删或覆盖。
- [ ] 由维护者确认代码、数据和权重的授权，再选择并添加适用许可证；不自动假定 MIT 等许可证。
- [ ] 增加贡献说明和 Issue/PR 模板，采用描述性提交信息。
- [ ] 干净克隆按 README 可运行，完成最小实验后不会将输出误加入提交。

**依赖：** Issue #1；产物归档策略与前两个任务的实验记录约定保持一致。
